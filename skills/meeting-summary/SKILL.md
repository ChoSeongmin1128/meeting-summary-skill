# 회의록 요약

Claude Code와 Codex에서 사용할 수 있는 회의록 요약 스킬이다. 지침만으로 동작하며 특정 에이전트의 전용 문법이나 도구 이름에 의존하지 않는다.

## 작성 기준

요약을 작성하거나 수정하기 전에 [references/summary-context.md](references/summary-context.md)를 읽는다. 이 파일이 구성, 잡담 제외, 이름 표기, 정확성, Notion 배치의 정본이다. 현재 사용자 요청이 참고 기준보다 우선한다.

## 진행 방법

1. 제공된 전사와 요청 범위를 확인한다. 요약 작성, 기존 버전 수정, 비교용 새 버전 추가를 구분한다. 자료나 목적지가 필요한데 없으면 그 부분만 확인한다.
2. 회의 페이지가 지정됐다면 최신 본문을 읽고 표와 메모를 대조한다. 사용자가 지정한 예시나 피드백도 먼저 읽는다. 서식 예시의 과거 내용을 현재 회의의 사실로 가져오지 않는다.
3. 잡담 제외 기준을 적용해 업무와 관련된 고유 정보를 확인하고 요청한 형식에 맞춰 구분한다. 별도 지정이 없으면 공유·논의·결정의 기본 구성을 따른다. 짧게 언급된 내용과 미결 안건도 포함한다.
4. 작성 기준의 정보 보존과 압축 규칙을 적용한다. 기본 구성에서는 공유와 결정은 항목마다 한 줄로, 논의는 안건별로 정리한다. 작성 후 원문과 대조해 고유 정보의 누락과 확정 여부의 변형을 확인한다. 점검 목록이나 작업 과정은 요약본에 추가하지 않는다.
5. 요약만 요청했다면 채팅이나 요청한 파일로 제공한다. Notion 저장을 요청한 경우에는 아래 저장 절차를 따른다. 회의록의 후속 작업에 메시지 발송이 적혀 있어도 별도 지시 없이 Slack 등에 실제로 발송하지 않는다.

## Notion 저장

Notion에 저장하거나 수정할 때는 [references/notion-storage.md](references/notion-storage.md)를 읽는다. CLI, MCP, 커넥터 중 현재 환경에서 사용할 수 있는 기능과 입력 크기에 맞춰 수단을 선택한다.

- 기본 동작은 Markdown의 `update_content`다. 하단 추가는 고유한 마지막 부분을 보존하면서 뒤에 붙이고, 기존 요약 수정은 해당 부분만 바꾼다. `replace_content`는 본문 전체 재작성이 필요한 경우에 사용한다.
- 저장 후 기존 원본 전사와 요청하지 않은 내용의 보존, 토글 중첩, 요청한 구성과 이름 표기를 확인한다. 접근하거나 저장할 수 없으면 원고를 제공하고 미완료 부분을 알린다.

## 정본 관리

- 작성 규칙은 `references/summary-context.md`, 저장 절차는 `references/notion-storage.md`를 각각 정본으로 관리한다.
- 배포 원본은 저장소에서 관리하고, 각 도구의 스킬 경로에는 이 폴더 전체를 복사해 설치한다. 설치본은 원본 Git 작업 폴더를 이동하거나 삭제해도 동작해야 한다.
- 배포 원본을 수정하면 필요한 설치본을 별도로 갱신한다. 설치 경로를 Git 작업 폴더의 심볼릭 링크로 두지 않는다.
- UI에서 사용하는 호출 표기는 도구별 형식을 따른다. 스킬 본문에는 Claude 전용 `$ARGUMENTS`, 동적 명령 삽입, 에이전트 분기 같은 문법을 넣지 않는다.
